# NIKKE QQ 机器人：词条统计功能实施方案

## 0. 范围与落地边界

本文用于实现以下功能：

```text
#词条导入 角色名       开始导入，默认接收 4 张装备截图
#词条导入 角色名 5     显式按 5 个槽位导入
#词条 角色名           查询该角色已确认的词条
#词条统计 角色名       生成单角色词条卡片
#词条统计 属性         生成多角色对比表
#词条导出              导出当前用户的 Excel 数据
#词条确认 / #词条重试 / #词条修正 / #词条取消
```

### 设计边界

- 不修改 AstrBot 核心。
- 现有会战命令继续走 `8793` 桥接服务，不改其路由。
- 词条功能作为 AstrBot 插件内的独立业务模块接入。
- 业务数据使用插件自己的 SQLite，不写入现有 `data/guild_war.db`。
- OCR 只处理用户主动发送的 QQ 图片，不做登录绕过、封包读取或内存读取。
- 收到命令或图片后 5 秒内先发送 ACK；OCR、渲染、导出全部在后台任务执行。
- 群聊和私聊统一使用 AstrBot 的 `event.unified_msg_origin` 作为回传会话。

## 1. 数据库设计

### 设计思路

以“用户 + 角色 + 装备槽位 + 词条”为最小事实记录。OCR 结果先写入历史表和会话 payload，只有用户确认后才写入正式词条表；这样 OCR 误识别不会直接覆盖已有数据。

SQLite 适合单机部署：WAL 模式、短事务、单进程写入即可满足群机器人使用。用户表、角色表、装备槽位和词条表保持规范化，查询时通过视图或聚合函数生成统计结果。

### 关键代码片段：建表与连接

```python

    image_sha256 TEXT NOT NULL,

    result_json TEXT NOT NULL DEFAULT '[]',

    status TEXT NOT NULL DEFAULT 'success',
    error_message TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, image_sha256)
);
CREATE TABLE IF NOT EXISTS import_sessions (
    user_id TEXT PRIMARY KEY,
    step TEXT NOT NULL,
    payload_json TEXT NOT NULL DEFAULT '{}',
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
"""

class EquipmentStore:
    def __init__(self, db_path: Path) -> None:
        self.db_path = db_path
        self.db_path.parent.mkdir(parents=True, exist_ok=True)
        with self.connect() as db:
            db.executescript(SCHEMA)

    def connect(self) -> sqlite3.Connection:
        db = sqlite3.connect(self.db_path, timeout=10)
        db.row_factory = sqlite3.Row
        db.execute("PRAGMA foreign_keys = ON")
        return db
```

### 注意点

- 不要使用表名 `user`，它在部分 SQLite 工具中容易与关键字/系统对象混淆，使用 `users`。
- 正式数据只能由“确认”流程写入；重复确认采用 `UPSERT`。
- 每个 QQ 用户独立保存数据。群聊只是触发位置，不要用群号替代用户号。
- `slot` 允许 1-5，默认 4 件；仅在角色配置或命令中明确指定时使用 5 件。
- `tier` 允许 0-15；`0` 表示没有可靠阶数结论，必须在确认前人工核对。
- 原图和 OCR 结果需要保留清理策略，默认保留 30 天，避免数据库和磁盘无限增长。

## 2. OCR 识别流程

### 设计思路

QQ 图片先通过 AstrBot `Image.convert_to_file_path()` 转成本地文件，并归档到插件数据目录的 `imports/YYYYMMDD/<sha256>.<ext>`，再按 SHA-256 查 OCR 缓存。当前代码对原图、灰度图、对比度增强图分别执行 RapidOCR，按纵向坐标合并同行并尝试相邻行组合；昵称、好友、QQ 号等不含合法词条名的文本会在后处理中过滤。模板裁切尚待真实脱敏截图标定，当前不能宣称已完成 UI 模板定位。

输出统一为：

```json
{
  "slot": 1,
  "affix_type": "攻击力",
  "affix_value": 8.2,
  "value_text": "8.2%",
  "tier": 2,
  "confidence": 0.91
}
```

### 识别顺序

1. 图片下载并计算 hash。
2. EXIF 旋转、缩放到长边 1600-2200 像素、转换 RGB。
3. 去除顶部昵称/头像区、底部操作区和左右黑边。
4. 使用 `assets/equip_templates/` 中的装备标题/槽位模板定位装备块。
5. 每个装备块按词条行切成 1-3 个 ROI。
6. RapidOCR 输出文本和置信度。
7. 文本归一化、正则提取属性名和数值、别名映射、阶数推断。
8. 低置信度或非法数值进入人工修正，不写正式表。

### 关键代码片段：RapidOCR 包装与后处理

```python
# guild_war_bot/wiki_query/ocr.py
from __future__ import annotations

import re
from dataclasses import dataclass
from pathlib import Path
from typing import Any

from PIL import Image, ImageOps

try:
    from rapidocr_onnxruntime import RapidOCR
except ImportError:  # 允许未安装 OCR 时插件仍能加载
    RapidOCR = None  # type: ignore[assignment,misc]

@dataclass(frozen=True)
class AffixHit:
    slot: int
    affix_type: str
    affix_value: float
    value_text: str
    tier: int
    confidence: float

VALUE_RE = re.compile(r"(?P<value>\d+(?:[.,]\d+)?)\s*(?P<unit>%|％|倍|秒)?")

class AffixOCR:
    def __init__(self, catalog: dict[str, dict[str, Any]]) -> None:
        self.catalog = catalog
        self.aliases = {
            alias: name
            for name, rule in catalog.items()
            for alias in [name, *rule.get("aliases", [])]
        }
        self.engine = RapidOCR() if RapidOCR is not None else None

    def preprocess(self, path: Path) -> Image.Image:
        image = ImageOps.exif_transpose(Image.open(path).convert("RGB"))
        max_side = max(image.size)
        if max_side > 2200:
            ratio = 2200 / max_side
            image = image.resize((int(image.width * ratio), int(image.height * ratio)))
        return image

    def recognize_text(self, image: Image.Image) -> list[tuple[str, float]]:
        if self.engine is None:
            raise RuntimeError("未安装 rapidocr-onnxruntime")
        image_array = np.asarray(image)
        if image_array.ndim == 3:
            image_array = image_array[:, :, ::-1]
        result, _ = self.engine(image_array)
        return [(str(row[1]), float(row[2])) for row in result or []]

    def normalize(self, text: str) -> str:
        text = text.replace("％", "%").replace("，", ".").replace("。", ".")
        return re.sub(r"\s+", "", text).replace("O", "0").replace("o", "0")

    def parse_line(self, slot: int, text: str, confidence: float) -> AffixHit | None:
        normalized = self.normalize(text)
        affix_type = next((name for alias, name in self.aliases.items() if alias in normalized), None)
        match = VALUE_RE.search(normalized)
        if not affix_type or not match:
            return None
        value_text = match.group("value") + (match.group("unit") or "")
        value = float(match.group("value").replace(",", "."))
        tier = explicit_tier_or_infer(self.catalog[affix_type], value)
        return AffixHit(slot, affix_type, value, value_text, tier, confidence)

def infer_tier(rule: dict[str, Any], value: float) -> int:
    for tier, values in rule.get("tier_values", {}).items():
        if any(abs(float(candidate) - value) <= 0.01 for candidate in values):
            return int(tier)
    return 0
```

`assets/equip_templates/` 建议按用途保存：

每个模板附带来源分辨率、裁切框、游戏版本和日期说明。模板只定位相对位置，不把固定坐标作为唯一识别手段。

### 鲁棒性建议

- 反光：同时保留原图、灰度图、对比度增强图三路 OCR，取置信度最高的合法结果。
- QQ 压缩：先放大 1.5-2 倍再 OCR；数值小数点允许 `.`、`,`、`·` 归一化。
- UI 变化：模板只负责锚点，词条 ROI 使用相对比例；模板失效时返回人工修正，不盲目点击或写库。
- 角色名干扰：角色名以用户命令为准，截图中的昵称/好友名只作为 OCR 文本，不参与角色绑定。
- 4/5 件装备：根据角色清单校验槽位数量，不足时继续提示用户，不把缺失槽位当作空词条。
- 不确定项：置信度低于 `0.80`、阶数为 `0` 或数值越界时必须进入确认/修正流程。

## 3. 对话状态机

### 设计思路

单机部署使用“内存快速访问 + SQLite 持久化”。内存字典保存当前任务对象，SQLite 保存状态和 payload；机器人重启后可以恢复 `WAITING_SCREENSHOT_N` 或 `WAITING_CONFIRM`，不会因为进程重启丢失用户导入进度。

状态定义：

```text
IDLE
  -> WAITING_SCREENSHOT_N
  -> WAITING_CONFIRM
  -> COMPLETE
  -> IDLE
```

每个用户同时只允许一个导入任务。30 分钟没有命令或图片交互则清理状态并删除临时图片引用。

### 关键代码片段：状态与超时清理

```python
# guild_war_bot/wiki_query/equipment_session.py
from __future__ import annotations

import asyncio
import time
from dataclasses import dataclass, field
from enum import StrEnum
from typing import Any

class Step(StrEnum):
    IDLE = "IDLE"
    WAITING_SCREENSHOT_N = "WAITING_SCREENSHOT_N"
    WAITING_CONFIRM = "WAITING_CONFIRM"
    COMPLETE = "COMPLETE"

@dataclass
class Session:
    user_id: str
    step: Step = Step.IDLE
    payload: dict[str, Any] = field(default_factory=dict)
    touched_at: float = field(default_factory=time.time)

class SessionManager:
    def __init__(self, store, timeout_seconds: int = 1800) -> None:
        self.store = store
        self.timeout_seconds = timeout_seconds
        self.items: dict[str, Session] = {}
        self.lock = asyncio.Lock()

    async def start(self, user_id: str, character_id: str, expected: int) -> Session:
        async with self.lock:
            session = Session(user_id, Step.WAITING_SCREENSHOT_N, {
                "character_id": character_id, "expected": expected, "images": [],
            })
            self.items[user_id] = session
            self.store.save_session(session)
            return session

    async def touch(self, user_id: str) -> Session | None:
        async with self.lock:
            session = self.items.get(user_id) or self.store.load_session(user_id)
            if not session or time.time() - session.touched_at > self.timeout_seconds:
                self.items.pop(user_id, None)
                self.store.delete_session(user_id)
                return None
            session.touched_at = time.time()
            self.items[user_id] = session
            self.store.save_session(session)
            return session

    async def cleanup_loop(self) -> None:
        while True:
            await asyncio.sleep(60)
            async with self.lock:
                expired = [uid for uid, item in self.items.items()
                           if time.time() - item.touched_at > self.timeout_seconds]
                for uid in expired:
                    self.items.pop(uid, None)
                    self.store.delete_session(uid)
```

### 指令语义

- `#词条导入 角色名`：解析角色名，创建/覆盖该用户的导入会话。
- 图片消息：只有用户处于 `WAITING_SCREENSHOT_N` 时才进入 OCR；普通图片不触发识别。
- 达到期望张数：进入 `WAITING_CONFIRM`，发送识别结果和操作提示。
- `#词条确认`：事务性写入正式词条表，状态改为 `COMPLETE`。
- `#词条修正 2 攻击力 8.2% 2`：修改当前待确认 payload 的第 2 槽词条。
- `#词条重试`：保留会话，重新处理最近一张失败图片。
- `#词条取消`：删除当前会话，不改正式数据。

### 注意点

- 不建议使用 Redis：当前是单机、单机器人、单进程，Redis 会增加部署依赖；未来多进程/多实例时再切 Redis。
- 不能只依赖内存字典，否则 AstrBot 重启会导致用户重复上传。
- 状态机写 SQLite 时使用短事务，OCR 不要在数据库事务内执行。
- 后台任务必须保存 `event.unified_msg_origin`，不能保存整个 event 对象。

## 4. 词条卡片渲染

### 设计思路

卡片采用固定宽度、内容自适应高度的 PIL 模板：顶部是角色立绘和角色名，中部显示词条合计和 5 条核心属性，底部按装备槽位展示 4-5 件装备。每行词条使用标准名、数值、阶数和置信度状态；最高值词条使用蓝色突出。

字体优先使用本机已有字体，避免依赖系统默认字体导致中文变方框：

```text
C:\Windows\Fonts\NotoSansCJK-Regular.ttc
C:\Windows\Fonts\SourceHanSansCN-Regular.otf
C:\Windows\Fonts\msyh.ttc
```

### 关键代码片段：PIL 卡片

```python
# guild_war_bot/wiki_query/catalog.py
from __future__ import annotations

from pathlib import Path
from PIL import Image, ImageDraw, ImageFont

FONT = Path(r"C:\Windows\Fonts\msyh.ttc")
BLUE = (50, 150, 255)
WHITE = (245, 245, 245)
MUTED = (170, 180, 195)
BG = (20, 27, 40)

def font(size: int) -> ImageFont.FreeTypeFont:
    return ImageFont.truetype(str(FONT), size)

def render_character_card(character: dict, rows: list[dict], portrait: Path | None, out: Path) -> Path:
    width = 1200
    top = 270 if portrait and portrait.exists() else 150
    height = top + 90 + max(1, len(rows)) * 58 + 40
    canvas = Image.new("RGB", (width, height), BG)
    draw = ImageDraw.Draw(canvas)
    if portrait and portrait.exists():
        art = Image.open(portrait).convert("RGB")
        art.thumbnail((220, 240))
        canvas.paste(art, (32, 24))
    name = str(character.get("cnName") or character.get("name") or "未知角色")
    draw.text((280, 35), name, fill=WHITE, font=font(42))
    total = sum(float(row["affix_value"]) for row in rows)
    draw.text((280, 100), f"词条合计：{total:.1f}%   词条数：{len(rows)}", fill=MUTED, font=font(25))
    core = character.get("core_affixes", [])[:5]
    draw.text((32, top - 45), "核心属性：" + " / ".join(core), fill=BLUE, font=font(25))
    best = max((float(row["affix_value"]) for row in rows), default=-1)
    for index, row in enumerate(rows):
        y = top + index * 58
        highlight = float(row["affix_value"]) == best
        color = BLUE if highlight else WHITE
        text = f"装备 {row['slot']}   {row['affix_type']}   {row['value_text']}   {row['tier']}阶"
        draw.text((42, y), text, fill=color, font=font(26))
    out.parent.mkdir(parents=True, exist_ok=True)
    canvas.save(out, "PNG")
    return out
```

### 注意点

- 立绘路径必须来自本地 `Nikke_Wiki` 资料，找不到立绘时仍然能生成纯数据卡片。
- 所有文字绘制都使用明确字体，不使用 PIL 默认字体。
- 不能只按“数值最大”判断优质词条；正式规则应结合属性类型和角色 `core_affixes`。
- 发送图片前确认文件存在、格式为 PNG/JPEG，失败时降级发送文字摘要。

## 5. 对比表生成与 Excel 导出

### 设计思路

`#词条统计 属性` 先按属性筛选，再按阶数降序、数值降序排序，最多展示 6-10 个角色。表格使用固定列宽，选中的角色或当前查询对象整行使用蓝色字体/浅蓝背景。

Excel 作为原始数据导出，不把 PNG 卡片反向解析成表格。导出文件通过 AstrBot `File` 消息段发送。

### 关键代码片段：PIL 对比表

```python
from PIL import Image, ImageDraw

        x = 30
        for value, (_, size) in zip(values, columns):
            draw.text((x, y), str(value), fill=BLUE if is_selected else WHITE, font=font(23))
            x += size
    out.parent.mkdir(parents=True, exist_ok=True)
    image.save(out, "PNG")
    return out
```

## 6. 性能与稳定性

### 设计思路

消息事件只做解析、ACK 和创建后台任务；CPU 密集的 PIL/OCR 工作放到线程池，避免阻塞 asyncio 主循环。OCR 以图片 SHA-256 做缓存，重复图片直接复用结果；单张图片失败只影响当前导入任务，不影响 AstrBot 和其他群消息。

### 关键代码片段：缓存、限流、后台任务

```python
import asyncio
import hashlib
from collections import deque
from time import monotonic

class OCRGate:
    def __init__(self, max_per_second: int = 2) -> None:
        self.max_per_second = max_per_second
        self.calls: deque[float] = deque()
        self.lock = asyncio.Lock()

    async def acquire(self) -> None:
        while True:
            async with self.lock:
                now = monotonic()
                while self.calls and now - self.calls[0] >= 1:
                    self.calls.popleft()
                if len(self.calls) < self.max_per_second:
                    self.calls.append(now)
                    return
                wait = 1 - (now - self.calls[0])
            await asyncio.sleep(max(0.05, wait))

def sha256_file(path: Path) -> str:
    digest = hashlib.sha256()
    with path.open("rb") as handle:
        for block in iter(lambda: handle.read(1024 * 1024), b""):
            digest.update(block)
    return digest.hexdigest()

async def run_ocr(ocr, path: Path, gate: OCRGate):
    await gate.acquire()
    loop = asyncio.get_running_loop()
    return await loop.run_in_executor(None, ocr.process, path)
```

### 稳定性规则

- 单用户串行：同一个用户的导入任务不同时处理两张图；不同用户可并发，但受全局限流限制。
- 超时：OCR 单图建议 20 秒，整批导入建议 90 秒；超时进入失败状态并给出重试命令。
- 异常隔离：后台任务顶部捕获 `Exception`，记录日志并向原会话发送“识别失败，可重试/修正”。不要吞掉 `CancelledError`。
- 磁盘清理：原图和渲染图按 hash/日期分目录，任务完成后可保留结果图 7 天、原图 30 天。
- 日志字段：`user_id`、`session`、`image_hash`、`slot`、`ocr_confidence`、`duration_ms`、`result`。
- 访问控制：默认任何群成员只能查看/导出自己的词条；管理员权限只用于维护和数据清理，不默认开放跨用户查看。

### 设计思路

- `Image.convert_to_file_path()`：图片组件转本地路径。

- `StarTools.get_data_dir()`：插件独立持久化目录。
- `StarTools.send_message()`：后台任务主动发送消息。

### 关键代码片段：插件入口与 5 秒 ACK

```python
from astrbot.api import logger
from astrbot.api.event import AstrMessageEvent, filter
from astrbot.api.message_components import File, Image
from astrbot.api.star import Context, Star, StarTools

class NikkeGuildBridgePlugin(Star):
    def __init__(self, context: Context, config=None) -> None:
        super().__init__(context)
        data_dir = StarTools.get_data_dir("astrbot_plugin_nikke_guild_bridge")
        self.catalog = AffixCatalog(data_dir)
        self.store = EquipmentStore(data_dir / "equipment_affix.db")
        self.sessions = SessionManager(self.store)
        self.ocr_gate = OCRGate(max_per_second=2)
        self.tasks: set[asyncio.Task] = set()

    @filter.event_message_type(filter.EventMessageType.ALL, priority=900)
    async def affix_message(self, event: AstrMessageEvent):
        command = parse_affix_command(event.message_str or "")
        image = next((item for item in event.message_obj.message if isinstance(item, Image)), None)
        if command is None and image is None:
            return
        if command is not None:
            reply = await self.handle_command(event, command)
            if reply:
                yield event.plain_result(reply)
            event.stop_event()
            return
        session = await self.sessions.touch(event.get_sender_id())
        if not session or session.step != Step.WAITING_SCREENSHOT_N:
            return
        # 先 ACK，不能等待图片下载或 OCR。
        yield event.plain_result("已收到截图，正在识别，请稍候。")
        task = asyncio.create_task(self.process_image(
            event.unified_msg_origin, str(event.get_sender_id()), image,
        ))
        self.tasks.add(task)
        task.add_done_callback(self.tasks.discard)
        event.stop_event()

    async def process_image(self, origin, user_id, image) -> None:
        try:
            path = Path(await image.convert_to_file_path())
            result = await run_ocr(self.catalog.ocr, path, self.ocr_gate)
            self.store.save_ocr(user_id, path, result)
            message, next_step = await self.sessions.accept_result(user_id, result)
            await StarTools.send_message(origin, MessageChain().message(message))
        except Exception as exc:
            logger.exception("词条 OCR 失败: %s", exc)
            await StarTools.send_message(
                origin,
                MessageChain().message("识别失败，可发送 #词条重试 或 #词条修正。"),
            )
```

> 上面是核心流程节选；完整实现以 `qq_bot/astrbot_plugin_nikke_guild_bridge/main.py` 为准。后台任务只保存 `origin`、QQ 号和图片组件，不保存整个事件对象。

### WikiIndex 共享

不要复制 196 角色词典。词条模块通过现有 `guild_war_bot.wiki_query.index.WikiIndex` 查询角色名、别名和立绘：

```python

        self.index = default_index()
```

### 集成注意点

- `COMMAND_ALIASES` 只能服务会战桥接命令；词条命令必须独立处理，避免被 POST 到 `8793`。
- 事件监听器优先级要高于通用 LLM 处理，词条命令和导入中的图片不能被 LLM 抢先消费。
- 词条图片处理后调用 `event.stop_event()`，避免同一消息既被词条插件处理又被人格/LLM 回复。
- 不要 `await OCR` 后才 ACK；先 `yield event.plain_result(...)`，再 `asyncio.create_task(...)`。
- `event` 对象本身不应长期保存；后台任务只保存 `unified_msg_origin`、用户 QQ、群号和图片路径。
- 插件重载/退出时取消后台任务，关闭 SQLite 连接由每次短连接上下文负责。
